# Development notes

Cyno Studio (`cyno-studio`, formerly pollo-api; Pollo is now just one provider). Durable notes on how this codebase is built and checked.

Before calling anything done run `ruff check`, `ruff format --check`, `basedpyright` (strict, no baseline), `pytest`, and in `src/js` `npm run lint`, `npm run format:check`, `npm test`. Lint and type rules are mandatory: no ignores, `noqa`, `type: ignore` or pyright baseline; fix the code. A suppression that is truly unavoidable needs the maintainer's approval first. Adding *stricter* rules is fine. Never submit real Pollo jobs (billable, no cancel or refund) without explicit per-run consent.

Layout: Python lives in `src/py/web/` (an import root: `src/py` is on the path, the package is still `web`), the Vue app in `src/js/`; `tests/`, `alembic/`, `scripts/` stay at the repo root. Paths below are relative to the repo root.

## Notes

- **Complexity:** `max-complexity` is 7 for Python (ruff) and for the frontend (ESLint, tests exempt); `max-lines` is 600 for frontend source. Stricter ruff rules enforced: `A`, `PLW`, `PLR0911/0912/0913/0915`, `PLR2004`, `FBT`. Test-only ignores for `PLR0913`, `PLR2004`, `FBT` are approved (see `pyproject.toml`). `EM` and `CPY` are noise here: not recommended.
- **Typed API:** `make gen-api` writes `src/js/src/api/schema.d.ts` (committed; CI fails when stale). Every endpoint has a Pydantic response model; `api/paths.ts` maps endpoint strings to routes so `api.get/put/...` are typed. Turn streams publish `TurnEvent` models as `text/event-stream` (`core/openapi.event_stream_only`). Server JSON is trusted from the schema at runtime (`readJson<T>`); if that bites, generate validators from the schema. Persisted browser state is read through `utils/storage.ts` / `readShape`, never trusted.
- **Frontend is all strict TypeScript:** no `.js` left; `vue-tsc` over `.ts` and `.vue`; ESLint `strictTypeChecked`; no `any`, no suppressions. Conventions: optional props are `x?: T | undefined` (`exactOptionalPropertyTypes`), templates read `props.x` where a default makes it non-optional, typed `InjectionKey`s in `injection.ts`, input values via `typedValue`, test rows from the factories in `__tests__/models.ts`. `useChat.ts` is deliberately the one facade over the typed API modules. `gen:api` passes `--default-non-nullable false`; the SPA catch-all route is `include_in_schema=False`.
- **Scoped CSS trap:** when a component is split, rules in the parent's scoped CSS stop reaching elements the children now own; use `:deep()` or move the rule (this caused the sidebar underline bug).
- **Audit script:** `audit_pollo_models.py --write` unhides only img2vid models, merges limits, keeps only `image` / `video` / `audio` refs, and leaves edit / extend models to a human (tests in `tests/test_audit_editor.py`). Run scripts via `make audit-models` / `make probe-models`.
- **Startup** fails fast: `ensure_schema` raises `MigrationFailedError`; with `restart: unless-stopped` a failing migration retry-loops (see `docker compose logs app`).
- **Rename:** the legacy `POLLO_DATA_DIR` / `${POLLO_HOST_DATA_DIR}` fallbacks are gone; a deployment still using the old names gets the repo root or an unset mount, so check `.env` first.
- Remaining `cast(` calls in `src/py` (34) are deliberate: TypedDict construction, Protocol shims for untyped libraries (Authlib, ASGI scope), ORM internals.
- **CI and releases:** `ci.yml` runs `lint`, `test-python`, `test-frontend`, `audit` and `docker` (builds and Trivy-scans both images, no push) on every PR; a ruleset on `main` requires all five and an up-to-date branch, squash merges only. On `main`, `build-and-push` bumps the tag from the squash-commit message (patch by default; `#minor` / `#major` in the PR title) and pushes `:latest` plus `:vX.Y.Z` for the app and nginx images. At least one tag must always exist, or the numbering restarts at 0.
- **Dependency policy (full audit 2026-11-17: Python 69 to 55 locked packages, frontend 290 to 281).** Fewer dependencies is the goal; each one is code we trust and an advisory feed we watch.
  - Add a library only when it replaces more code than it costs to trust. Do not patch around a broken dependency (`overrides`, `audit fix --force`); replace the library, or accept a finding that is dev-only and write it down here.
  - Every direct dependency must be imported by our code, or needed by name at runtime with a comment in `pyproject.toml` saying by what. Re-run the check when adding or removing one: for each package, grep for its import in `src/py`, `scripts`, `tests`; see what requires it (`uv tree --invert --package X`); remove it and run the whole suite. Removed on this pass: `openai` (never imported), `httpx` (Authlib uses `httpx2`), `pip-system-certs` (`httpx2` uses the OS trust store via `truststore`; the built image verifies Pollo, OpenRouter and Venice), `beautifulsoup4` (one lookup, now stdlib `html.parser`, with tests), `uvicorn[standard]` extras (uvloop, httptools, websockets, watchfiles; no WebSockets, and one user), `@vitest/coverage-v8` (no coverage run), and `opencv-python` became `opencv-python-headless` (same API, no GUI libraries, so the Dockerfile and CI lost their apt lines and the image went 242 MB to 155 MB).
  - Kept, and why: `itsdangerous` (starlette's sessions), `python-multipart` (uploads), `@types/node` (the type-check fails without it), `@vue/test-utils` (24 test files; its `js-beautify` chain is the dev-only audit finding above). Still open to question: `opencv-python-headless` itself (only video length and a first frame; ffmpeg would also be a heavy dependency) and `anyio`/`python-dotenv` as direct entries (each is imported by one file, so they stay).
  - Accepted, not open: `npm audit` reports 5 moderate dev-only findings, all one chain (`@vue/test-utils` > `js-beautify` > `editorconfig` / `glob` > `minimatch`), used only by `wrapper.html()`, which no test calls. Looked at 2026-11-17; no way out that removes it (`@testing-library/vue` is built on `@vue/test-utils`; `@vue/test-utils@2.4.11` still has 4; `overrides` and `--force` are ruled out above; our own mount helper means ~1,000 call sites and a harness we would have to trust). Nothing ships from it and the production audit is clean (CI enforces that). Re-open only if `@vue/test-utils` drops `js-beautify`, or an advisory gains a path that runs in our tests.
- **Dependencies:** Python deps are ranges in `pyproject.toml` with the exact versions in `uv.lock` (`make lock`, `uv sync`); the dev tools (ruff, basedpyright, pytest, pre-commit) are the `dev` group. Dependabot is **security-only for the application dependencies** (uv and npm: security PRs open as soon as an advisory has a fix; routine bumps are off, so a TypeScript or Vite major is a manual, deliberate change). Docker images and GitHub Actions still get weekly version updates, because the advisory database does not cover container images. Every version update waits 14 days after its release (`cooldown`), so a freshly published version is not proposed straight away; security updates skip the wait. `dependabot-automerge.yml` turns on auto-merge for all of them, so they merge once green and up to date; after one merges, the next needs "Update branch" if it did not conflict.
